# 宝石店 設計

## 概要

旧 `gem_store.cgi`（宝石店）の宝珠購入・売却・配送・加工（合成）・鑑定・整頓を再構築する。宝石・レシピ・鑑定プール・価格・宝珠箱容量の式はコードと [OpenAPI](../api/base.json) が正本である。根拠は `party2/lib/` 配下。

## 旧仕様との差分と注意点

- **配送の受信上限**（`gem_store.cgi:219–261`、旧 `get_you_gem_box_c`）：受信者の所持数を**送信者**の転職回数から求めた容量と比べる。このため宝珠箱が自分の容量を超えることも、空きがある宝珠箱への配送が低段階の送信者から拒否されることもある。[配送容量](depot.md#delivery-capacity-by-caller)の決定どおり、旧挙動のまま残す。
- **容量で拒否するのは購入と配送だけ**：鑑定と加工は旧 `send_gem` と同じく容量を確認せず、宝珠箱が容量を超えてもよい。
- **購入**は定価の5倍を払う（`gem_store.cgi:129–171`）。
- **未照合の差分**（#947）：Go は売却額に最低1Gを設けているが、旧実装にはない。整頓は Go がカタログ順、旧実装は保存 kind・番号の数値順（`gem_store.cgi:266–281`）。会話の旧5行目（販売中の宝石名入り）は省いている。

### Gatewayと参照・未移行操作

6操作はすべて Gateway のコマンドで実行し、参照は `gemstore` scene が担う。宝石店の REST は登録しない。旧実装の名前指定は ID 指定に置き換え、対象未指定時の候補表示は scene と明示入力で代える（旧 dispatch は `gem_store.cgi:100–106`）。scene は旧店頭と同じく、操作者の段階で買える宝石だけを表示する。各コマンドの施設ログ書き込みと presence の再現は #947、購入条件は #1135、レシピ解決は #1134 の未照合事項であり、transport 移行は完全なゲーム仕様互換の根拠にならない。
